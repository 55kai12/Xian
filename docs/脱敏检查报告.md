### 8.4 ⚠️ 踩到的坑（重要，会再犯）

**`git-filter-repo` 结尾那步 `git gc --prune=now` 会把这台机器上的仓库整个清空。**

- 现象：改完历史后 124 个提交 / 1831 个对象**全没了**，所有 ref 变成
  `invalid sha1 pointer`；`git fsck` 报 `bad object HEAD`。
- 原因：本机沙箱有「批量删除保护」，`git gc --prune=now` 被半途拦截，
  新对象还没落稳就被清掉。
- 处置：靠事先做好的 `pristine.git` 镜像克隆还原（`mv .git` → `cp -r pristine.git .git`
  → 改回 `core.bare=false`、重设 `remote.origin`、`git reset --hard`），
  再用 `_tmp_cmp/fr_no_gc.py` **包一层、把 cleanup 里的 repack 强制关掉**重跑。
- ⚠️ **推论**：在这台机器上**不要**手动跑 `git gc --prune=now`；
  本地遗留的未引用旧对象就让它留着（无害，只是占点盘）。
