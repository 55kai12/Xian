## 1. 定位与边界

**做什么**：轻量、可重复、以「天」为单位的打卡记录。名字、颜色、频率、每日目标次数、打卡历史、连续天数、提醒。

**不做什么**：不占番茄钟、不进专注记录、不进专注统计。这是它与「重复任务」的根本区别。

**与现有「重复任务」的关系**：现在用「每天重复的任务 + 跳过标记」也能勉强当打卡用，但那套模型带着优先级、预计贤时、分类、截止时间，
且一开就全部变成习惯。本功能**独立一套数据**，两条路互不干扰：

| | 重复任务 | 小习惯打卡 |
| --- | --- | --- |
| 场景 | 有工作量、要专注的事（背单词） | 只是「今天做了几次」 |
| 是否占贤时 | 占 | 不占 |
| 进专注统计 | 进 | 不进 |
| 主体数据 | 任务 + 每天快照 | 习惯 + 打卡日志 |

## 2. 数据模型（DB v11 → v12）

### 2.1 `habits`

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | Int PK 自增 | 导出时的「编号」 |
| `name` | String | 习惯名，如「早起」「喝水」 |
| `color` | Int | 色值，复用现有六色调色板 |
| `freqType` | String | `daily` / `weekly`（每周 N 次）/ `custom`（指定星期） |
| `weeklyTarget` | Int | `weekly` 用；`daily` 恒 7，`custom` 恒 0 |
| `weekDaysMask` | Int | `custom` 用；位掩码，bit0=周日 … bit6=周六 |
| `targetPerDay` | Int | **每日目标次数**，默认 1。1 = 普通打卡；>1 = 计数型（「喝水 8 杯」） |
| `startDate` | Long | 起始日（当天 0 点），此前的日期不算未完成 |
| `remindMinutes` | Int | 提醒时刻（当天第几分钟）；**-1 = 不提醒**。与任务的 `dueTimeMinutes` 同一套表示 |
| `sortOrder` | Int | 拖拽排序 |
| `deletedAt` | Long | 回收站时间戳，0 = 未删 |
| `createdAt` | Long | 创建时间 |

### 2.2 `habit_logs`

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | Int PK 自增 | |
| `habitId` | Int | → `habits.id` |
| `day` | Long | 打卡日（当天 0 点） |
| `count` | Int | **当天累计次数**。一天一条，点一次 +1；减到 0 时直接删掉这一行 |
| `createdAt` | Long | 首次打卡时刻 |

唯一索引 `(habitId, day)` —— 一天一行，重复打卡在数据库层就挡住。

> 「一天一行 + count」而不是「打一次插一行」：后者一天能插几十行，列表查询要 `GROUP BY`，
> 导出也会变成一堆重复行。前者一条记录就是一天的答案。

### 2.3 达标、连续天数（streak）

- **达标**：`count >= targetPerDay`。目标为 1 时就是「打了没」。
- `daily` 习惯：从今天往回数**连续达标**的天数，中间断一天就归零。
- `weekly` / `custom` 习惯：**不算连续天数**，改显示「本周 3/5」。
  理由：每周 N 次的「连续」定义含糊（跨周怎么算），强行算出来用户也看不懂，
  不如直接给本周进度。

判定逻辑只写一处（`HabitStreak`），页面与统计都问它——与 `RepeatRule` 同样的理由：
两份实现一旦漂移，就会出现「列表显示 5 天、统计说 3 天」。

## 3. 页面与交互

### 3.1 打卡页 `HabitFragment`（新建，全屏，与倒数日/便贴同构）

```
┌──────────────────────────────┐
│ ← 小习惯            ＋       │   标题栏（返回 + 新建）
├──────────────────────────────┤
│ 今天 · 9月16日 周三           │   今日达标 3/5
│ ▓▓▓▓▓▓░░░░                   │
├──────────────────────────────┤
│ ● 早起              连续 12 天  ✓ │   目标 1：点一下即达标
│ ● 喝水              0/8        ○ │   目标 8：点一下 +1
│ ● 阅读              3/5        ○ │
│ ● 跑步          本周 2/3       ○ │   每周类：显示本周进度
└──────────────────────────────┘
```

- **单击圆钮 = +1**；达成后按钮显示 `✓`，再点提示「今天已经完成了」；
- **长按圆钮 = 撤销今天的打卡**（弹确认框）。长按不好发现，所以**首次打卡后弹一次 Toast 提示**；
- 点行本身 = 打开编辑对话框（本期不做详情页）；
- 空状态：「还没有习惯，点右上角新建」。

### 3.2 新建 / 编辑对话框

名称、颜色（六色圆点）、频率（每天 / 每周 N 次 / 指定星期三选一）、每日目标次数、提醒时间（可关）。
沿用 `TaskDialogs` 的对话框风格。⚠️ 自定义 view 不用 weight（沿用既有教训）。

### 3.3 删除

软删除进回收站，Toast「已移入回收站」，与任务/倒数日/便贴一致。删除时一并撤掉提醒闹钟。

## 4. 提醒

复用现有 `ReminderScheduler` 管道，但它原本是**一次性**闹钟（任务到期、倒数日提前提醒都只响一次）。
习惯要每天响，所以给它加一个**自我重排**能力：

- `ReminderScheduler.schedule(..., repeatDaily = true)`：闹钟触发后，`ReminderReceiver`
  发完通知**自己算下一天并重排**（纯时间运算，仍然不碰数据库，不破坏「接收器不查库」的现状）；
- 新增 `HabitReminderScheduler.sync(ctx, habit)`：算出下一次触发时刻（今天的该时刻已过就排明天），
  不提醒或习惯已删则 `cancel`；
- **requestCode 区间**：任务从 1 起、倒数日 500000 起 ⇒ 习惯用 **700000 + habitId**，
  通知 id 用 **5000 + habitId**，三套不撞车；
- **开机重排**：`BootReceiver` 里补一段（与任务/倒数日同样的理由——不补，重启后提醒全失效）；
- **重排挂在哪**：挂在 `HabitViewModel.refresh()` 里，不是只挂在「保存」上。只靠保存时排的话，
  **导入进来的、以及升级前就存在的习惯永远不会响** —— `TaskViewModel` 早就踩过同一个坑。
  refresh 是这一页唯一的入口（打开页面、打卡、编辑都会经过），`sync` 幂等、不读库，代价可忽略。
- **权限**：保存习惯后调 `ExactAlarms.requestIfNeeded(ctx)`，挂进那 5 处现有调用点的口径。

**已知取舍**：到点就提醒，**不判断今天是否已经达标**。判断要读数据库，与「接收器不碰数据库」冲突；
绝大多数打卡类应用也是固定闹钟。文案写成中性的「该打卡了」而不是「你还没打卡」。

## 5. 备份契约（第 9、10 张表）

沿用现有约定：**文件名 ASCII、内容中文、值一律人话化、编号押最后一列、导入端按列位置读**。

### 5.1 `habits.csv`

```
名称,频率,每周目标,指定星期,每日目标,提醒时间,颜色,开始日期,排序,编号
早起,每天,0,,1,06:30,墨绿,2026-09-01,0,1
阅读,每周,2,,1,,古铜金,2026-09-01,1,2
喝水,每天,0,,8,,黛蓝,2026-09-01,2,3
跑步,指定星期,0,周一、周三、周五,1,22:00,朱砂,2026-09-01,3,4
```

- `频率`：`每天` / `每周` / `指定星期` **三种之一**（导入端也兼容 `daily`/`weekly`/`custom`，
  以及手工写的「每周 3 次」—— 数字会被捞出来当每周目标）；
- 具体参数**各占一列**，不写成一句「每周 3 次」：一句话里夹着数字，Excel 里筛选和求和都用不上。
  所以「每周」看 `每周目标` 列、「指定星期」看 `指定星期` 列；
- `指定星期`：`周一、周三、周五`（顿号分隔，**周一排最前**；导入端的单字写法「一、三」也认）；
- `提醒时间`：`HH:mm`，空 = 不提醒；
- `排序`、`编号` 是两个**不能砍**的内部列（同任务表的理由）。

### 5.2 `habit_logs.csv`

```
习惯编号,打卡日期,次数
1,2026-09-15,1
1,2026-09-16,4
3,2026-09-16,1
```

- **一天一行**（与库里的 `HabitLog` 一致），不是打一次一行 —— 后者一年下来能堆出几千行重复日期，
  反而看不出「哪天打了几次」；
- 打卡记录会很多（10 个习惯 × 一年 ≈ 3650 行），所以单独一张表，不塞进 `habits.csv`；
- **回收站里的习惯不进备份，它的日志也就不进**（与子任务「父任务还在才导出」同一条原则）——
  否则文件里多出一堆认不出主人的行。导入端同样按「习惯在不在」过滤一遍；
- 导入时「次数」缺省为 1，兼容手工编辑漏填。

### 5.3 新增点

- `DataBackup`：加两个 `Sheet`（`habitsSheet` / `habitLogsSheet`），`SHEET_ENTRIES` 再加两项；
  另加星期名表 `WEEK_DAY_NAMES`（周日打头，与 `Habit.maskOf` 的位序一致）与
  书写顺序 `WEEK_DAY_ORDER`（周一打头）；
- `DataRestore`：`parseSheetHabit` / `parseSheetHabitLog` + `weekDayMask` 反解；
  仓库层加 `restoreHabits` / `restoreHabitLog`（已有的 `restoreHabitLog` 正好复用）；
  **旧布局（单文件 `data.csv`）一行不动** —— 老格式里没有习惯，恒报 0 条；
- `_tmp_cmp/format_check.py`：契约从 8 张表扩到 10 张，并新增「习惯两张表的接线」
  与 **1..127 星期掩码往返**（目前 **337 项全过**）；
- `README.txt`（zip 内）两行说明。
