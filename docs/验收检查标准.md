# 贤 · 功能验收检查标准

> 适用：Android 端「贤」，`applicationId = com.xian.focus`，`minSdk 26` / `targetSdk 35`
> 配套：`docs/更新日志.md`（版本改动记录）、`.workbuddy/memory/MEMORY.md`（工程约定）
> 版本基线：v2.0.72（本清单随功能一同维护，新增功能必须补对应条目）

---

## 使用说明

**编号规则**：`模块前缀-序号`，编号一经分配不再变更。报障时直接引用编号，例如「`TSK-07` 挂了」。
模块前缀：`ENV` 发布前置 / `TMR` 计时 / `TSK` 任务 / `REV` 复盘 / `LCK` 锁机 / `LKS` 锁机设置 / `LCM` 锁机模式 / `LIM` 应用限额 / `CD` 倒数日 / `HAB` 习惯 / `NTE` 便贴 / `FTN` 运势 / `SET` 设置 / `TRS` 回收站 / `BAK` 备份 / `REM` 提醒 / `HLT` 健康守护 / `ADP` 适配 / `CON` 一致性专项。

**优先级**：

| 级别 | 含义 | 处置 |
| --- | --- | --- |
| P0 | 阻塞发布。挂了不能发版 | 必须修复后才能出包 |
| P1 | 功能正确性。能发但用户会碰到 | 当版修，或明确记入日志的已知问题 |
| P2 | 观感与体验 | 可延后，但不允许累积超过两版 |

**三档验收**：

1. **冒烟**（附录 A，约 10 分钟）—— 每次改完代码随手过一遍，只覆盖主路径。
2. **常规**（第 2–16 章）—— 改动涉及某模块时，该模块全过。
3. **全量**（第 0 章 + 全部 + 第 17–19 章）—— 正式发版前必过。

**执行注意**：

- 凡标「边界」的条目，是历史上真实踩过的坑，**不要跳过**。
- 凡涉及权限、ROM 行为的条目（锁机、限额、提醒），**必须在真机上验**，模拟器结论不作数。本机主力机建议 ≥ Android 14，另建议备一台国产 ROM 机（vivo / 小米 / 荣耀任一台）验厂商适配。
- 「预期」写得含糊的条目等于没有标准，遇到这类条目请直接反馈补精确。

## 0. 发布前置（自动化硬校验）

这一章全部可在命令行完成，**任何一条不过就不出包**。

- [ ] **ENV-01 版本号三件套之一：编号递增**（P0）
  ```
  grep -nE "versionCode|versionName" PomodoroFocus/app/build.gradle.kts
  ```
  预期：`versionCode` = 上一版 +1，`versionName` = 上一版 +0.0.1，两者同步递增。
  边界：**回退代码时编号也要朝前走**，回用旧号会让手上升级包报 `INSTALL_FAILED_VERSION_DOWNGRADE` 装不上。

- [ ] **ENV-02 版本号三件套之二：更新日志**（P0）
  打开 `docs/更新日志.md`，预期：顶部状态行含当前版本且状态正确（待发版 / 已发布），正文有对应版本小节。
  边界：**日志没写 = 这次更新没做完**，不允许只改代码就交差。

- [ ] **ENV-03 版本号三件套之三：出包与归档**（P0）
  ```
  cd PomodoroFocus && ./gradlew assembleRelease --offline
  ```
  预期：`BUILD SUCCESSFUL`，无 `e:` 开头的错误行。
  然后旧包改名 `release/贤-<上一版>.apk`，新包复制为 `release/贤.apk`。**历史版本 APK 全部保留**。
  边界：本机 JDK 路径与构建代理**刻意不写在仓库里**（放在仓库外的 `~/.gradle/gradle.properties`），
  换机器要自己配一次；若 Gradle 报找不到 JDK，临时 `export JAVA_HOME='<本机 JDK 17 目录>'`。

- [ ] **ENV-04 签名校验**（P0）
  ```
  <本机 SDK 目录>/build-tools/35.0.0/apksigner.bat verify --verbose --min-sdk-version 21 "release/贤.apk"
  ```
  预期：`v1 scheme (JAR signing): true`、`v2 scheme: true`、SHA-256 为 `f675510a…`。
  边界：**必须带 `--min-sdk-version 21`**，否则会误报 `v1: false` —— 那不是坏了。同时确认 `build.gradle.kts` 里 `enableV1Signing = true` 仍在（国产 ROM 校验 v1）。

- [ ] **ENV-05 包内版本与签名者**（P0）
  ```
  <本机 SDK 目录>/build-tools/35.0.0/aapt2.exe dump badging "release/贤.apk" | head -3
  ```
  预期：`versionCode` / `versionName` 与源码一致，`package: name='com.xian.focus'`，`sdkVersion:'26'`、`targetSdkVersion:'35'`。

- [ ] **ENV-06 备份格式自检**（P1）
  ```
  python _tmp_cmp/format_check.py
  ```
  预期：342 项全过（含导出表列序 ↔ 导入端下标一致性、Room 建表语句 ↔ 迁移语句逐字比对）。
  边界：第 7 层迁移比对**要求先编译过**（`assembleRelease`），没编译会打 SKIP —— 不是通过。
  边界：**下标错位不报错**，只会把「排序」当「编号」静默写进库，只能靠这个脚本拦。

- [ ] **ENV-07 资源改动读回核对**（P1）
  ```
  A=<本机 SDK 目录>/build-tools/35.0.0/aapt2.exe
  "$A" dump resources "release/贤.apk" > _tmp_cmp/r_new.txt
  diff _tmp_cmp/r_old.txt _tmp_cmp/r_new.txt
  ```
  预期：差异行与本次源码改动**一一对应**，没有多余项。
  边界：**看包内资源要按实际路径查**。R8 资源压缩会短化重命名，`ic_launcher_foreground.png` 在包里可能叫 `res/Wn.png`，布局 `res/layout/fragment_note.xml` 可能叫 `res/2U.xml` —— 按原名 grep 查不到**不代表没打进去**，先用 `dump resources` 查出实际名。

- [ ] **ENV-08 工作区状态**（P1）
  ```
  cd <仓库根> && git status --short
  ```
  预期：只有本版该有的改动。`_tmp_cmp/`、扫码截图等临时产物**不得进入提交**。

- [ ] **ENV-09 离线可构建**（P1）
  预期：`--offline` 能过。若报 `journal-1.lock（拒绝访问）`，是别的 Gradle 版本守护进程占着共享缓存（`./gradlew --stop` 查不到），用 `taskkill /F /PID` 清掉。

## 1. 安装、启动与升级兼容

- [ ] **ENV 包在真机上装得上**（P0）
  覆盖安装 `release/贤.apk` 到装有上一版的机器，预期：安装成功，**数据不丢**（任务、记录、习惯、便贴、倒数日全在）。

- [ ] **UPG-01 跨版本升级不崩**（P0）
  从上一版直升，预期：首次启动不闪退、无 ANR。
  边界：涉及数据库结构变更时，**必须从「装过旧版的机器」升上来验**，全新安装验不出迁移问题。当前 `focuslist.db` 版本 **12**，迁移链 1→12 全在。

- [ ] **UPG-02 迁移后表结构正确**（P0）
  升级后进各页面（任务 / 倒数日 / 习惯 / 便贴 / 复盘）均能正常读出旧数据。
  边界：Room 开库时逐字段比表结构，对不上会抛 `IllegalStateException` —— 表现为**启动即崩**，编译期不报。这是迁移写错的典型症状。

- [ ] **UPG-03 升级后权限状态**（P1）
  升级后「我的 → 设置 → 锁机运行状态自检」逐项核对。
  边界：**覆盖安装后无障碍服务读窗口的能力会失效**，需要在系统设置里关开一次开关；未重开时 App 应自动退到「使用记录」数据源而不是直接失效。

- [ ] **STA-01 冷启动路径**（P1）
  杀后台后冷启动，预期：默认落在任务页，主题、壁纸、每日目标、抽屉里的各项计数（倒计时日数、便贴数、习惯摘要）都与本地数据一致。

- [ ] **STA-02 后台保留**（P1）
  切到后台再回来，预期：计时状态、锁机状态不被重置；抽屉摘要刷新正确。

## 2. 计时（TMR）

- [ ] **TMR-01 首次进入与默认值**（P1）
  全新安装进计时页，预期：状态为 IDLE，显示 25:00；「暂停」按钮置灰。

- [ ] **TMR-02 计时设置取值范围**（P1）
  点「计时设置」，预期仅 3 项：专注时长 1–480 分钟（默认 25）、短休息 1–60（默认 5）、长休息 1–60（默认 15）。
  边界：越界值应被拒绝或夹取，不允许写入非法值后窗口显示 `00:-30`。

- [ ] **TMR-03 开始 / 暂停 / 继续 / 重置**（P0）
  - 开始 → 数字倒数走；底部按钮文案：IDLE =「开始专注」、PAUSED =「继续」、其余 =「重新专注」
  - 暂停 → 数字停住；继续 → 从暂停处接着走，**不回起点**
  - 重置 → 直接回 IDLE 并清空当前 session
  - 边界：IDLE 与 PAUSED 态下「暂停」按钮必须置灰不可点

- [ ] **TMR-04 阶段流转**（P0）
  连续完成 4 个专注 → 第 4 个结束后自动进**长休息**；未完 4 个则进**短休息**；短休 / 长休结束一律回 IDLE（**不自动开始下一轮**）。
  边界：这是写死的规则（`POMODOROS_BEFORE_LONG_BREAK = 4`），当前**没有**循环次数设置。

- [ ] **TMR-05 结束时落库**（P0）
  专注段自然走完，预期：写一条 `PomodoroRecord(type=focus, isFinished=true)`；若绑定了任务则任务 `completedPomodoros +1`，达到 `estimatedPomodoros` 时任务自动标完成。
  边界：绑定的若是**重复任务模板**，不加完成计数。

- [ ] **TMR-06 计时通知**（P1）
  计时中通知栏常驻（频道 `focus_timer`，低优先级、静音、`onlyAlertOnce`），内容含阶段名与 `mm:ss`；专注结束时发一条高优先级「专注完成」通知。
  边界：**全程无声音、无振动**（代码里就没有），这是当前设计，不是漏做。

- [ ] **TMR-07 前台服务存活**（P0）
  计时中锁屏、切后台、划掉最近任务，预期：计时不中断、通知仍在。

- [ ] **TMR-08 时区 / 时间跳变**（P1）
  计时中手动改系统时间，预期：不出现负数倒计时、不崩溃。
  边界：倒计时用 `phaseEndAt` 墙钟反推，不用每秒累加；恢复 session 时若已过期**不补记**，直接回 IDLE。

- [ ] **TMR-09 锁机开关联动**（P1）
  计时页打开「锁机」开关，预期：隐藏底部导航、沉浸全屏、屏幕常亮。
  关闭后恢复正常。开着时按返回键的行为可预期（不出现黑屏卡死）。

- [ ] **TMR-10 起锁前置校验**（P0）
  未授予悬浮窗 / 无障碍权限时点开始，预期：弹窗拦截并说明原因，**不进入计时**。

- [ ] **TMR-11 应用锁 PIN**（P1）
  设 4 位纯数字 PIN；非 4 位、含非数字应被拒。设置后计时页进入需要验证。

- [ ] **TMR-12 每日目标**（P1）
  点「设每日目标」，默认 8，允许 ≥1 的整数；保存后在复盘页与专注统计里生效。
  边界：**目标值只能在计时页改**，不能只在复盘页加个按钮。

- [ ] **TMR-13 专注统计弹窗**（P2）
  显示今日 / 近七日 / 累计 / 累计分钟 + 周柱状图，数字与复盘页同一口径。
  边界：口径 = 计时完成次数 + 当天勾选完成的任务数，两处**必须一致**。

- [ ] **TMR-14 按钮禁态一致性**（P2）
  已完成的关联任务，「计时」按钮应置灰。所有置灰按钮都要真的点不动（不能只改色）。

## 3. 任务（TSK）

- [ ] **TSK-01 新建任务的完整字段**（P0）
  弹窗字段：标题（必填，空则拒）、分类（生活 / 工作 / 自定义）、日期（今天 / 明天 / 选日期 / 无）、备注、重复、预计贤时（1–99，默认 1）、多行子任务、图片、「写入系统日历」开关。
  边界：`priority` 高 1 / 中 2（默认）/ 低 3；`listType` 默认「未分类」；分类名是**用户数据，不可翻译**。

- [ ] **TSK-02 日期与到期**（P1）
  - 有截止日期的任务在当天与逾期时按规则显示
  - 无截止日期的普通任务**只在「今天」显示**
  - 重复任务无 `dueDate` 时以 `createdAt` 当天 0 点为锚点

- [ ] **TSK-03 完成 / 取消完成**（P0）
  勾选后进入「已完成」段，取消可退回。峰值动画只在「上次未完成 → 本次完成」这一次播放，重复勾选不重放。

- [ ] **TSK-04 滑动操作四按钮**（P0）
  左滑露出：完成 / 恢复、上移一行、下移一行、删除。动作区占可用宽 60%，单块 ≤64dp，滑过半宽才展开，松手 200ms 吸附；**同时只允许一行展开**，滚动或拖拽时自动收起。

- [ ] **TSK-05 拖拽排序**（P1）
  长按拖动可排序，**不跨「未完成 / 已完成」两段**。
  边界：上 / 下移与拖拽只回写 `templateId == 0` 的真实行，避免改掉重复模板的锚点日期。

- [ ] **TSK-06 子任务**（P1）
  行内展开显示「已完成 / 总数」，点圆点切换完成态；编辑弹窗可增删行。
  边界：子任务编辑是「删光重插」，必须按**标题 + 出现顺序**配对恢复完成态 —— 否则改个标题就丢全部勾选。
  边界：列表序号是派生值不在 `Task` 内，DiffUtil 看不见，改动后需手动 `notifyItemChanged`，否则序号不动。

- [ ] **TSK-07 从任务直接开始计时**（P1）
  行内「计时」按钮 → 启动计时并自动跳到计时页；已完成任务该按钮置灰。

- [ ] **TSK-08 重复规则四种**（P0）
  `none` / `daily`（每天）/ `weekly`（同星期几）/ `monthly`（同几号），锚点为 `dueDate`。
  边界：重复模板的 `isCompleted` **必须恒为 false**，否则往后每天都显示已完成且取消不掉。
  边界：由模板带出的虚拟实例必须**显式 `isCompleted = false`**，不能继承模板脏值。
  边界：重复判定列表与统计**必须共用同一个 `RepeatRule.covers`** —— 两份实现漂移会出现「清单看不见，趋势线却计一笔」。

- [ ] **TSK-09 删除重复任务三选一**（P0）
  仅删除这一次 / 删除全部该事件 / 删除全部但保留已完成 —— 三个选项都要验，尤其是「仅这一次」后第二天仍应出现。

- [ ] **TSK-10 跳过当天**（P1）
  跳过记录只存 `<模板id>@<当天0点>` 一条，当天快照仍留在库里。
  边界：**统计侧必须传 `skipped` 过滤**，否则出现「任务删了，趋势线还在计一笔」。

- [ ] **TSK-11 分组与分组颜色**（P2）
  分类色未设置时按分类名哈希在 6 个预设色里兜底，设置后固定不变（同一分类每次进来颜色一致）。

- [ ] **TSK-12 日历抽屉**（P1）
  任务页顶部日历：折叠态 = 周条（左右滑翻周），下拉展开 = 整月日历；月份文案正确（**`Calendar.MONTH` 从 0 起，`+1` 必需**）。
  边界：跨月翻页、跨年翻页不出现「13 月」或重复月份。
  ⚠️ **切周后的选中日见 TSK-16**（v2.0.92 起语义变更）。

- [ ] **TSK-16 周条切周后的选中日**（P1）（v2.0.92 起）
  收起态左右切周后，选中日期一律落在**新一周里离原位置最近的那一天**：
  - **前进一周 → 下一周的第一天（周一）**；
  - **后退一周 → 上一周的最后一天（周日）**。

  即「切周前后在接缝处接得住」。以今天周一 9/21 为例：
  后退 → 9/20（周日）；从周三 9/23 后退 → 也是 9/20；从周六 9/26 后退 → 还是 9/20。

  边界：
  - 一周从**周一**起（`setWeekStarWithMon()` / `mondayOfWeek()` 用 `Calendar.MONDAY`），周六/周日不是一周末尾 —— 别按周日开头算。
  - 当前选中日只要落在本周内，上一周里离它最近的**必然是上周日**、下一周里离它最近的**必然是下周一**，
    与「原来停在周几」无关 ⇒ 实现上不必再读 `selectedDate`（`onSwipeLeft` 直接 `= weekStartMillis`、
    `onSwipeRight` 直接 `= weekStartMillis + 6 * DAY_MILLIS`）。
  - ⚠️ **此语义 v2.0.92 起变更，此前是「保持同一星期几」（±7 天）** —— 那条是 v1.5.9 定的（见 `更新日志.md` v1.5.9「左右切周时保持相同星期几的日期选择」）。
  - 切周后周条高亮、下方任务清单、趋势线三者必须同步换到新周新日期（`setWeek` + `loadWeekTrend` + `renderCurrentList` 一个都不能落）。
  - 已知取舍：**来回切完不回到出发那天**（9/23 →后退→ 9/20 →前进→ 9/21）。这是「最近一天」规则的必然结果，
    不是 bug；若要「来回回到原处」需改成「仅周一后退 / 周日前进时对接」。

- [ ] **TSK-13 任务备注与图片**（P2）
  备注可长文、图片可加 / 删 / 全屏预览；「显示备注」关闭时列表不显示。

- [ ] **TSK-14 节假日标记**（P2）
  开启后日历上有节假日标记（春节 / 端午 / 中秋 + 清明 + 元旦 / 劳动 / 国庆）。
  边界：**不处理调休**，这是已知范围，不是 bug。

- [ ] **TSK-15「昨天未完成」横幅**（P1）（v2.0.89 起）
  昨天有未完成的事时，**当天首次**打开任务页（且停在今天）→ 列表上方浮出墨色横幅：
  「昨天，您有 N 个事件尚未达成」+ 「全部移到今天」/「查看详情」/「今日不再提醒」。
  - 「全部移到今天」：昨天那几条真的出现在今天的清单里，并 Toast 提示移了几条。
  - 「查看详情」：列出昨天未完成的标题；点一条跳到**昨天**那天的清单。
  - 「今日不再提醒」：横幅消失，当天再打开也不出现；**次日恢复**（不受影响）。
  - 横幅出现后当天不再出现（即便离开再回来）；第二天自动重置。
  - 边界：**只在「今天」这一天下弹**。用户翻到别的日期时不弹 —— 在 3 天前的视图里
    弹「昨天有 3 个未完成」会很错乱。
  - 边界：**数据源必须复用 `buildOccurrencesForDay(pendingTasks, 昨天)`**，
    不得另写一套过滤。统计口径与清单口径一旦分家就会各说各话（历史上栽过）：
    重复任务的虚拟实例、`TaskSkipStore` 跳过、`dueDate == null` 归今天等边界全在那个函数里。
  - 边界：昨天没有未完成项时**不显示**（不是显示「0 个」）。
  - 边界：**重复任务「移到今天」必须落到今天**，不能只改模板的 `dueDate` ——
    模板是**规则**、不是某一天的事，改它会污染锚点（表现为后续重复日期整体漂移）。
    正确做法：在目标日写一条快照（`templateId = 模板id`）。配套 `TaskDao.getSnapshotOn()`
    （**不限 `isCompleted`** —— 原有的 `getCompletedSnapshot` 查不了未完成快照）。
  - 边界：目标日已有该模板快照时**不重复插入**。
  - 边界：`YesterdayBannerState` 的状态**刻意不进备份**（一次性状态），
    「今日不再提醒」是设备本地行为。
  - 边界：横幅四个色值**不跟主题走**，四套主题下同一个样子（对齐用户给的截图）。
  - 边界：`fragment_tasks.xml` 里的 `<include>` **必须带 `android:id`**，viewBinding 才展开
    子视图；被包含布局的**根不能带同名 id**（会撞）。Kotlin 侧访问子控件走
    `binding.yesterdayBanner.<子控件id>`，根走 `binding.yesterdayBanner.root`（**不是 `binding.yesterdayBanner`**）。

- [ ] **TSK-16 重复任务的子任务「按天独立勾选」**（P0，v2.0.94 起）—— **重点回归项**
  建一个「每天」重复的任务，带两条子任务。**9-19 勾掉第一条 → 切到 9-20，该条必须仍是未勾**；
  9-20 勾掉再回头切到 9-19，9-19 的勾选**不受影响**。
  ⚠️ 边界：**普通任务（非重复）行为必须与 v2.0.93 完全一致** —— 一行一子任务、完成状态跟任务走、不按天分。
  边界：库内行数 = 「模板行（`dueDate IS NULL`，只存标题定顺序）」+「有勾选的天各一条」，
  **不随天数复制整个标题列表**。
  边界：给重复任务**新加**一条子任务后，切到**过去**的日期也要看得见它（显示未勾）——
  渲染是「模板行的标题 ↔ 那天的记录」按标题配对，配不上现造一条未完成的。
  边界：编辑重复任务的子任务标题时**只删模板行**（`deleteTemplatesByTaskId`），
  各天的勾选记录必须留着 —— 改个标题不该把这周勾过的全清掉。
  边界：编辑弹窗回填子任务时**只读模板行** —— 连各天记录一起回填，保存一次子任务列表就翻一番。
  边界：子任务按天的日期取 `startOfDay` 归一 —— 周条点击、周切、日历选日三处传进来的毫秒
  未必都是零点口径，不归一就会「存进去查不出来」、点了没反应。
  边界：`day` 拿不到时退回老路径（宁可这次按模板行改，也不写一条日期不明的记录）。

  在白名单应用里（尤其横屏游戏、边缘滑动返回）触发窗口事件误报时，锁机层**不得盖下**：
  盖屏前 `evaluate()` 会问「窗口栈（免权限）→ 使用记录（兜底）」两级免疫源，
  任一源说前台在白名单里就否决盖屏并撤层。
  边界：真机**没授「使用情况访问」**时窗口栈这条路必须独立生效 —— 它不依赖任何权限；
  两源都拿不到（无障碍被清 + 未授权）时退回原行为，不许因此崩。
  边界：无障碍服务销毁后 `foregroundFromWindowStack()` 返回 null（弱引用），不持死引用。

- [ ] **LCK-15 清后台的完成反馈**（P1）—— **重点回归项**（v2.0.74 起，v2.0.81 改）
  锁机层点「清空后台应用」后，**必须立刻有可见反馈**：按钮文字临时变成
  「已清理后台应用」，2 秒后还原为「清空后台应用」。
  边界：**反馈里不得出现「清理了几个」的数字**（v2.0.81）—— `killBackgroundProcesses`
  不回传任何结果，而「后台到底有几个应用」在 Android 上也问不到：`getRunningAppProcesses()`
  从 5.1 起只返回调用者自己的进程、使用记录要 `PACKAGE_USAGE_STATS`、`/proc` 读不到别的 uid。

  「已清理 100 多个」—— 宁可只说"已清理"，不报一个编出来的数。
  边界：反馈画在锁机层自己身上，不依赖 Toast —— 锁机时贤是后台应用，
  vivo 等 ROM 会静默丢弃后台 Toast（2026-09-17 真机踩坑）。
  边界：反馈期内层被撤掉（锁机结束 / 切回白名单），不得崩溃、不得残留回调改写别的按钮。
  边界：清的是**缓存进程**（`killBackgroundProcesses` 的系统硬限制）—— 带常驻服务 / 推送通道的
  应用（微信等）杀不掉，这是所有免 root 第三方"一键清理"的共同上限，**不算缺陷**。

- [ ] **LCK-16 锁机中改 / 取消定时时段要密码**（P0）—— **重点回归项**（v2.0.88 起）

  预期落盘后：本次改动生效，但**本月退出额度不变**（`LockExitQuota.remaining` 前后相同）。
  边界：**没在锁机时不得有任何打扰** —— 直接落盘。这道闸只防「锁机正跑着抽走依据」，
  不是用来防用户改设置的。
  边界：**闸门必须架在落盘那一刻**（与白名单同一套路子）。入口拦只挡得住一半：
  用户可以在时段列表编辑到一半时锁机开始，再按保存。
  边界：**不能共用 `LockPinPanel`** —— 它靠 `<include>` 内嵌悬浮层、用 `root.findViewById(R.id.exitPinOverlay)`

  边界：`SettingsFragment.clearAllData()` 与 `DataRestore` 的 `LockMachineScheduler.cancel/schedule`

- [ ] **LCK-17 锁机层让开手机锁屏（安全）**（P0）—— **重点回归项**（v2.0.89 起）
  锁机期间按电源键息屏，再按电源键亮屏：应当看到**手机自己的锁屏 / 密码键盘**，
  能正常输入密码进入手机；**不得**被锁机层挡住。
  - 密码输完解锁后：回到非白名单应用 ⇒ 锁机层应**自己盖回来**；回到白名单应用 / 桌面 ⇒ 不盖。
  - 锁机期间息屏放着（超过几分钟）再亮屏解锁，锁机**仍须生效**（别出现「锁机自己失效了」）。
  - 边界：**不能只判 `isInteractive`**。`ACTION_SCREEN_ON` 之后、密码输完之前，屏幕是亮的、
    锁屏还在 —— 而那正是用户要输密码的时刻。判据必须两路都上：
    `KeyguardManager.isKeyguardLocked`（锁屏在位）与 `PowerManager.isInteractive == false`（息屏），
    任一为真即让开。两路都免权限；取值失败（`runCatching` 返回 null）时**按屏幕可用处理**
    （宁可盖着，也别因为读不到系统状态就整层失踪）。
  - 边界：让开必须走 `hide(force = true)`，且判定位置在 `evaluate()` 与 `tick()` 里
    **都排在退出流程判断之前** —— 否则「让开」会先被当成一次前台离开。
  - 边界：让开期间 `pendingLeaveSince` 要清零，不能把这段算成宽限期消耗。
  - 边界：**`hide()` 绝不能停 tick**（`removeCallbacks(tickRunnable)`）。锁机是否继续 tick
    只看 `keepTicking`（锁机是否还 active），与层在不在无关 —— 停了 tick，
    解锁后就再没人把层盖回来。tick 自续写成 `try { tick() } finally { if (keepTicking) postDelayed(...) }`，
    单次 `tick()` 抛异常不能把整条链掐断。
  - 边界：层被让开时 `view == null`，而 tick 仍要能拿到 `Context` ⇒ 必须留 `lastContext`
    （`show()` / `hide()` 两处都提前赋值）。
  - 边界：**来电 / 通话不受影响**（既有行为，回归确认别破坏）。

  边界：**忘记密码无找回**，只能清数据重来 —— 这是设计取舍，界面应说明。

- [ ] **LKS-05 两个密码开关独立**（P1）
  「退出锁机需密码」「应用限额加时需密码」各管各的，共用同一套密码。交叉验证四种组合。

- [ ] **LKS-06 锁机语录**（P2）
  一条一个输入框，可增删改，实时显示「共 N 条」；**空框不保存**；「恢复默认」只摆回编辑框**不落盘**（要保存才生效）。默认 4 条。

- [ ] **LKS-07 PIN 不进备份**（P1）
  导出 zip 中**不得包含** PIN 哈希；导入到新机后需要重设密码。
  边界：这是刻意的安全取舍。同理不进备份的还有：退出锁机月度额度、应用限额当日用量。

- [ ] **LKS-08 改白名单的闸门**（P0）—— **新增于 v2.0.84**
  三个入口（白名单二级页、锁机 Tab 的白名单按钮、番茄钟自定义锁机弹窗里的白名单按钮）
  在改动白名单前统一过 `WhitelistGate`：
  - **锁机进行中**（`LockMachineController.isActive()`）→ 一行都不给改，弹「白名单已锁定」；
    选择器那两个入口**连弹窗都不开**（别让用户白挑一场），二级页把这一下勾退回去。
  - **距下次定时锁机开始 ≤ 1 小时**（`LockMachineScheduler.nextStartAt()`，没排时段时不成立）
    → 先过 30 秒冷静期（`WhitelistGate.COOLDOWN_SECONDS`），倒计时走完「确认修改」才可用。
  - 其余情况（含刚过完冷静期的 2 分钟内）→ 直接落盘，不打扰。
  边界：闸门架在**落盘那一刻**、不是入口 —— 选择器是异步开的，用户可能挑到锁机都开始了才按保存。
  所以二级页被拦下时必须用 `AppGridAdapter.setSelection()` 把勾退回落盘那份，
  **不许留「看着选中、其实没存」的假状态**（比直接不改更让人困惑）。
  边界：冷静期里锁机可能已经开始（定时时段正好卡在中间）→ 确认时**重新查一次** `isLocked()`，
  已开始则不放行，原地把对话框改成「白名单已锁定」，不再另弹一个。
  边界：一次冷却是**闸门级**的（`PASS_WINDOW_MILLIS` = 2 分钟），不是每点一个应用等 30 秒 ——
  否则勾三个应用要等一分半，「防冲动」会变成「防使用」。隔久了再改要重新冷却。
  边界：**备份导入不做闸门**（`DataRestore` 直写 `saveWhitelist`）—— 那是用户自己带进来的整份数据，
  不属于「现场改设置」，在导入链路里插一个冷静期对话框没有意义。

- [ ] **LKS-09 自定义分钟数记住上次的值**（P2）—— **新增于 v2.0.86**
  锁机 Tab 的自定义输入框与番茄钟自定义锁机弹窗**共用同一份记忆**
  （`LockMachineController.customMinutes` / `saveCustomMinutes`）：敲下数字即存，下次进页面直接预填。
  - ⚠️ 预填时**圆点必须同步选中「自定义」**：`toggleLock()` 是「圆点说了算」的，
    只填值不选圆点会让用户看着框里 45、实际按 30 分钟锁 —— 比不预填更坑。
    且这一步要放到**下一帧**（`binding.root.post {}`）做，直接跟在 `setText` 后面实测不稳。
  - 番茄钟那个弹窗**没有**「自定义」圆点，取值直接读输入框，所以只需预填。
  边界：值随 `settings.csv` 的「锁机自定义时长(分钟)」进备份；`0` 表示还没用过（不预填）。

## 7. 锁机模式（LCM）

- [ ] **LCM-01 与普通锁机的区别体现**（P1）
  锁机模式有独立前台服务（通知**不可见**，见 `LCM-07`）、退出额度、冷静期、密码、白名单、统计；
  普通锁机无额度 / 冷静期，只有长按退出。
  两者**不应互相串状态**（例如普通锁机退出时不应扣锁机模式额度）。

- [ ] **LCM-02 冷静期 30 秒**（P0）
  长按退出 → 弹确认 + 30 秒倒计时 → 期满 → （若有密码）验密 → 扣额度 → 退出。
  **应用内停止与覆盖层长按都必须走这 30 秒**。
  边界：贤自己永远在白名单里，若不走冷静期，「在自己的 App 里直接停」就架空了整个约束。

- [ ] **LCM-03 额度扣减时机**（P0）
  同上 `LCK-08` / `LCK-09`：只在 `stopLock()` 扣一次；自然到期不扣；用完给明确反馈。

- [ ] **LCM-04 跨日时段结束**（P1）
  23:00 → 次日 07:00 这类时段结束时**自然到期**，不扣额度，切回白天状态正常。

- [ ] **LCM-05 锁机中不记应用限额**（P1）
  锁机进行中不累计应用限额用量，也不显示限额层（避免两层遮罩叠加）。
  这是两条链路的明确分界，改任一侧都要回来验这条。

- [ ] **LCM-06 前台服务被系统回收**（P0）
  锁机中划掉后台 / 系统内存回收后，预期：`GuardService` 能拉回；无法拉回时**给出明确状态提示**，不出现「以为在锁、其实没锁」的静默失效。

- [ ] **LCM-07 锁机通知不出现在通知栏**（P1）—— **重点回归项**（v2.0.78 起）
  锁机生效期间：**下拉通知栏与状态栏都不得出现贤的锁机通知**
  （原来的「自定义锁机运行中 / 锁机中：剩余 mm:ss / 停止锁机」按钮），
  同时前台服务仍在运行、锁机层照常盖住非白名单应用。
  边界：**必须是频道重要性 `NONE`**（`lock_machine_channel_v2`），
  不能只做 `setSilent` / `setPriority(MIN)` / `setOngoing(false)` —— 那些仍在下拉里看得见。
  边界：旧频道 `lock_machine_channel` 必须已删除，不许在「设置 → 通知 → 贤」里留僵尸频道。
  边界：**Android 13+ 系统自己会往通知栏放一条「后台运行的应用」汇总**（以及快捷设置里的
  「正在运行的应用」入口），那是系统发的、应用删不掉 —— 验收时不许把它算成「没藏住」，
  判据是**贤自己发的通知不存在**。
  边界：退出锁机仍必须有路可走（覆盖层长按 / 应用内「停止锁机」/ 设置页关定时锁机），
  通知栏那条按钮消失后**额度、冷静期、密码一样都不能少**。
  边界：**通知里不得带任何 action**（`addAction`）—— 那颗「停止锁机」已于 v2.0.79 从代码里删除。
  即使通知不可见也不许留着：哪天某个 ROM 把通知显示出来，它就是一条绕过额度 / 冷静期 / 密码的后门。
  边界：通知左侧那个方块图标由应用**自备**（`NotifyIcon.large()`，v2.0.93 起）。
  ⚠️ 不设 `setLargeIcon` 时 ROM 会拿系统缓存的**应用图标**顶上，而那份缓存**覆盖安装后不刷新**
  （v2.0.91 实测：桌面已是新图标、通知里还是旧的），所以「它自己会跟着 launcher icon 变」是**错的**。
  状态栏的小图标是 `android.R.drawable.ic_lock_idle_lock`（系统锁形），与方块图无关。

- [ ] **LCM-08 锁机期间不能进入系统设置**（P0）—— **重点回归项**（v2.0.79 起）
  锁机生效期间打开「设置」（桌面图标、最近任务、下拉通知栏里系统那条
  「正在其他应用的上层显示内容」警告的跳转，任意一条路径），都必须**被锁机层立刻盖住**，
  不能留下任何可操作的窗口期。
  边界：判定用的设置包名必须**本机反查**（`Settings.ACTION_SETTINGS` resolve 出来的那个），
  不许只写死 `com.android.settings` —— 各 ROM 设置包名不统一，写死必漏。
  边界：对设置**不给宽限**（`grace = 0`）。普通应用那 300ms 宽限是为了吃掉手势误判
  （「滑到一半又滑回去」），设置不需要：点开设置是明确意图，300ms 足够点掉一个开关。
  边界：锁机层此刻没显示时（例如从通知栏跳转触发的冷启动）也必须立刻补盖，不能「漏一次」。
  边界：来电 / 通话界面不受此条影响，仍然永远放行 —— 接不了电话是安全问题，优先级最高。
  已知取舍（刻意）：锁机期间改不了任何系统设置，含 WiFi / 蓝牙等开关。
  设置是锁机唯一真正的出口：关掉「显示在其他应用上层」锁机层直接失效，
  关掉应用通知在部分 ROM 上会让应用连带被限制后台、锁机起不来。

- [ ] **LCM-09 锁机期间不能下拉通知栏**（P0）—— **重点回归项**（v2.0.80 起）
  锁机生效期间从屏幕顶端下拉，通知面板**必须立刻被收回去**：点不到任何通知，
  也点不到面板里那些通往设置的入口（那条路是 LCM-08 想堵的，能在面板里点就等于漏了）。
  边界：这是**事后**拦截 —— 悬浮窗（`TYPE_APPLICATION_OVERLAY`）在系统状态栏面前没有
  任何优先级，没有 root 拦不住「下拉」这个动作本身。允许面板闪一下，但**不许停住不动**。
  边界：判据两条同时成立才算「面板展开」—— systemui 的 `TYPE_SYSTEM` 窗口 + 高度超过屏幕 1/4。
  只看包名会把「状态栏刷新」当成下拉（状态栏窗口一直存在）；只看高度在个别 ROM 上会误报。
  ⚠️ **不许再加回「窗口拿着焦点」这条判据**（v2.0.80~2.0.82 的教训）：锁机层自己是
  `TYPE_APPLICATION_OVERLAY` 且可获焦，下拉时焦点**不会**转给面板 ⇒ 该判据恒为 false、
  整段逻辑一次都不执行。真机实证：面板 `mHasSurface=true` 展开着，`mCurrentFocus` 仍是
  `com.xian.focus type=2038`。
  边界：包名校验只认「含 `systemui`」—— 别拿 `SYSTEM_UI_PACKAGES` 这个集合来认面板，
  它里面还装着 vivo 的侧滑返回层 `com.vivo.upslide`（同样是 TYPE_SYSTEM、也可能铺满屏）。
  边界：收起用 `GLOBAL_ACTION_BACK`，必须带节流（`SHADE_COLLAPSE_INTERVAL_MILLIS`）——
  按住往下拖是连发事件，没节流会一下按出一串返回。
  ⚠️ **收面板的尝试只许挂在 `WINDOW_STATE_CHANGED` 上，不许再挂 `WINDOWS_CHANGED`**（v2.0.94 的教训）。
  `TYPE_WINDOWS_CHANGED` 对每一次窗口层级变动都上报（IME 弹/收、应用内弹对话框、分屏拖动），
  它分不出「下拉通知栏」和「用户正在打字」；而判错时代价是 `GLOBAL_ACTION_BACK` **退掉底下的应用** ⇒
  白名单应用里一打字就被连续按返回弹回桌面（用户报的「锁机抽风、一直返回」+「用不了键盘」是同一根因）。
  通知面板从「不可见」变「可见且拿到焦点」**必然**产生 `WINDOW_STATE_CHANGED`，只留这一条不会漏拦。
  边界：`collapseNotificationShade()` 里**看到 `TYPE_INPUT_METHOD` 窗口就直接返回** ——
  有输入法就不动，宁可这一轮不拦面板，也不冒「把用户正在打的字退没」的风险。
  边界：无障碍服务被系统清掉时本项失效（退化回「可下拉」），不许因此崩、
  也不许影响前台判定等其他逻辑。

## 7.5 锁机与输入法（IME，v2.0.94 起）

- [ ] **IME-01 白名单应用里打字不被弹回桌面**（P0）—— **重点回归项**
  锁机生效中，进入白名单应用、点开任一输入框打字，**不许出现「连按返回、弹回桌面」的抽搐**。
  边界：键盘必须真的弹得出来（含搜狗/讯飞/语音等第三方输入法）——
  用户报「锁机时用不了键盘」时，根因是上面的误返回，不是输入法被禁用。
- [ ] **IME-02 前台报的是输入法时不盖锁机层**（P1）
  判据：前台包名**本身是输入法**（`SystemAppAllowlist.isInputMethod`）**且**无障碍窗口栈
  确认有 `TYPE_INPUT_METHOD` 窗口 ⇒ 按「用户还在原来那个应用里打字」处理，不盖。
  ⚠️ 边界：**不许写成「有 IME 就不盖」** —— 那样「弹着输入法切到非白名单应用」会漏锁
  （输入法不一定随切换立刻收起）。两个条件必须同时成立。
  边界：拿不到窗口信息（无障碍没开）时不放行，行为退化为与 v2.0.93 一致。
- [ ] **IME-03 密码面板能弹出键盘且不被遮挡**（P0）
  长按「退出锁机」→ 出现密码面板 → 键盘**必须自动弹出**（`SHOW_FORCED` + `restartInput`，
  不能再用 `SHOW_IMPLICIT`：非 Activity 悬浮窗的 `requestFocus()` 常不被认成输入意图）。
  键盘弹起时面板**自己上移**（`liftPanelAboveKeyboard`），「确认 / 取消」两个按钮**不许被键盘压住**。
  ⚠️ 边界：不能只靠窗口的 `SOFT_INPUT_ADJUST_RESIZE` —— 锁机层窗口带 `FLAG_LAYOUT_NO_LIMITS`
  （横屏铺满必需），它让窗口不受 IME 影响，ADJUST_RESIZE 形同失效。
  边界：面板关闭时位移要复位（否则下次打开还顶在半空中）。
  边界：三套浮层（锁机 / 专注锁 / 应用限额）**共用同一个 `LockPinPanel`**，改一处即三边生效 ——
  验收时至少覆盖「锁机长按退出」与「应用限额加时」两个入口。

## 8. 应用限额（LIM）

- [ ] **LIM-01 添加入口与默认值**（P1）
  任务页抽屉 → 应用限额 → 「添加应用」复用锁机的选择器；**新勾选默认 30 分钟**。
  边界：**加限额是收紧，直接生效**；**取消勾选是放宽**，必须与 LIM-02 走同一套三道闸
  （提醒 → 30 秒冷静期 → 密码），取消后当日用量保留（见 LIM-09）。
  多选取消时提醒文案要**列出被取消的应用名**，不能只说「N 个应用」。

- [ ] **LIM-02 额度档位与边界**（P0）
  预设 15 / 30 / 45 / 60 / 90 / 120 分钟 + 无限制。
  **每一条放宽路径都必须过三道闸**（收紧要放过）：
  ① 提醒（说清已用照算、改低立刻锁死、取消不归零）→
  ② 30 秒冷静期（确认键禁用倒计时，走完才可点）→ ③ 密码（若「应用限额需要密码」开着）。
  两个入口：列表弹窗调节额度（含选无限制）、选择器里取消勾选。**新增第三个入口时必须回来确认它过闸**。
  边界：调到 **≤ 今日已用量** 时保存即锁死，提醒文案里必须提前说清。
  边界：冷静期弹窗的确认键在倒计时期间必须真的 **disabled**（不是点了没反应）；中途取消不产生任何写入。

- [ ] **LIM-03 到时的遮罩行为**（P0）
  用满额度后出现全屏遮罩盖住该应用：显示应用名、今日可用额度、加时按钮、回桌面按钮。**不抢焦点**，返回 / Home 可用。

- [ ] **LIM-04 临时解锁（加时）**（P1）
  加时按钮**每次 +15 分钟**，**每月全局共 3 次**（不按应用各给）。开了「应用限额需要密码」时，加时**与调整限额时长**前都须验 PIN（同一开关管两处）。
  边界：次数用完时按钮要禁用并说明 —— 与退出额度同理，不允许点了没反应。

- [ ] **LIM-05 计时来源与权限降级**（P0）
  优先用系统「使用情况访问」；无该权限时退回无障碍每秒累加。**两者互斥**（靠心跳切换），不允许同时累加导致用量翻倍。
  两者都没有时应给出明确提示，而不是安静地不计数。

- [ ] **LIM-06 跨天 / 跨月重置**（P0）
  跨天：当日用量归零、锁重新生效。跨月：加时次数与「本月被锁次数」重置。
  边界：**限额当日用量的重置依赖正确的日期口径**，改系统日期前后各验一次。

- [ ] **LIM-07 统计显示**（P1）
  页头「累计 X 分钟 · N 个应用」；每行显示「已用 / 额度」或「已锁定」；每 3 秒自刷新。被锁次数按「应用 × 天」去重。

- [ ] **LIM-08 守护存活**（P1）
  划掉后台后 1.5 秒内自动拉回；拉不回时限额不能静默失效。

- [ ] **LIM-09 重设限额不归零当日用量**（P0）—— v2.0.78 新增
  选「无限制」（或选择器取消勾选）后，**同一天再设回限额，今日已用必须还在**、照算不归零。
  边界：`setLimit(0)` 只删 `limit:`，`used:` / `bonus:` 留到次日 rollover 清；
  已用量超过新设额度时保存即锁定（这是预期，不是 bug）。
  边界：**两条放宽路径都要验**（弹窗选无限制 / 选择器取消勾选），只测一条会漏。

## 9. 倒数日（CD）

- [ ] **CD-01 新建流程与默认值**（P1）
  抽屉 → 倒数日 → 右上「+」：标题（必填，空则提示）、备注、**历法切换（公历 / 农历，默认公历）**、目标日期（**默认今天 +7 天 0 点**）、「每年重复」切换（**农历态下该开关不显示**）、6 色圆点（墨绿 / 古铜金 / 赭石 / 黛蓝 / 朱砂 / 玄墨）；编辑态多「删除」。

- [ ] **CD-02 显示规则**（P1）
  右侧 24sp 粗体天数 +「天后 / 天前」；已过期用灰色；左侧 4dp 颜色条；每年重复的在日期后追加「·每年」。
  农历条目显示「农历 八月十五 · 2026-09-25」（农历名 + 今年的公历落点），**不追加「·每年」** —— 农历自带年复一年的含义，再加显得啰嗦。

  这是**唯一按「第一列的名字」读回的表**（约 27 行）。写入端每写一个名字，解析端**必须同名认领**。
  边界：少认领一个 = **导入成功但那一项设置静默没回来**，不报任何错。改这张表必须两边成对改。
  边界：导入端**空值与 0 一律跳过**（不覆盖用户已设值）。

- [ ] **BAK-08 其余表按下标读**（P0）—— **重点回归项**
  除 `settings.csv` 外**全部按列位置读**（`row[14]` 这种）。改 `DataBackup` 任何一张表的列序**必须同步改 `DataRestore`**。
  边界：**下标错位不报错**，只会把「排序」当「编号」静默写进库。只能靠 `_tmp_cmp/format_check.py` 拦 —— 改完必跑。

- [ ] **BAK-09 导入端容错**（P1）
  - BOM 必须摘掉（`removePrefix("\uFEFF")`），否则旧版首个**小节标题认不出，任务段被静默丢弃**
  - 日期一律 `SimpleDateFormat(..., Locale.US)` 且每次新建实例
  - 日记图片只在备份确实带图时才写

- [ ] **BAK-10 往返一致性**（P0）
  导出 → 清除数据 → 导入，预期：任务（含子任务与完成态）、记录、倒数日、习惯（含打卡日志与连续天数）、便贴（含星标与时间）、限额、日记、设置**逐项复原**。

- [ ] **BAK-11 导入后主题与壁纸**（P2）

## 16. 提醒与通知（REM）

- [ ] **REM-01 精确闹钟权限主动申请**（P0）—— **重点回归项**
  权限要**主动要**，挂在这 5 处：保存锁机时段 / 新增任务 / 编辑任务 / 倒数日 / 习惯。
  边界：Android 14+ 不默认授予。**只写一个按钮让用户自己去找 = 不算完成**（用户明确否决过这种写法）。
  边界：新增闹钟**只走 `ExactAlarms.schedule()`** 这一个入口（拿不到权限自动退化成不精确，不抛异常），异常也只在这一个入口兜。

- [ ] **REM-02 任务提醒**（P1）
  到点通知正确；重复任务按规则排下一次。

- [ ] **REM-03 倒数日提醒**（P1）
  目标日前 N 天 09:00 发通知；每年重复的顺延逻辑正确。

- [ ] **REM-04 习惯提醒**（P0）
  每天固定时刻响一次；**导入进来的习惯、升级前就存在的习惯也必须能响**（见 `HAB-06` 的重排挂载点）。

- [ ] **REM-05 requestCode 不冲突**（P1）
  任务 1+ / 倒数日 500000+ / 习惯 700000+（通知 id 3000+ / 5000+）。
  边界：`cancel` 不传标题也能命中（只看 requestCode + action + component）。

- [ ] **REM-06 重启后提醒仍在**（P0）
  重启手机，预期：所有提醒重新排上（开机补排）；补排过程不闪退。
  边界：历史 bug —— 缺精确闹钟权限时锁机时段与开机补排会**闪退**。

- [ ] **REM-07 通知权限**（P1）
  Android 13+ 未授予通知权限时，应有引导；不能静默什么都收不到。

- [ ] **REM-08 通知点击跳转**（P2）
  点通知跳到正确页面；「锁机保护已失效」类通知跳无障碍设置。

- [ ] **REM-09 通知大图标由应用自备**（P1，v2.0.93 起）
  全部通知（守护 / 锁机 / 锁机结束 / 健康自检 / 目标提醒 / 计时中 / 专注完成，**共 7 处**）
  都显式设了 `setLargeIcon(NotifyIcon.large(...))`。
  图在运行时合成：`ic_launcher_background` 铺满 + `ic_launcher_foreground` 内缩 1/6
  （与 adaptive icon 的 18dp/108dp 同比例），256×256，按进程缓存一次。
  预期：下拉通知栏里那个方块**始终是贤的图标**，不再受 ROM 的应用图标缓存摆布。
  边界：**不设 `setLargeIcon` 就等于把这一格交给系统缓存** —— 覆盖安装后常常不刷新，
  表现为「桌面已经是新图标、通知里还是旧的」（v2.0.91 实测）。**新增通知必须一并设置。**
  边界：⚠️ 这条**不是一次装好就生效的**。系统那份缓存若已经脏了，仍需**重启手机**
  （或清「系统界面」缓存）才会彻底一致；`setLargeIcon` 的作用是让通知**从此**不看系统脸色。
  边界：别为了这一格去改 launcher icon 资源 —— 那是另一回事，改了也没用（见 `LCM-07` 的边界）。

## 17. 权限、健康自检与守护（HLT）

- [ ] **HLT-01 四类权限申请路径清晰**（P0）
  悬浮窗、无障碍、使用情况访问、精确闹钟 —— 各自有明确入口，缺的时候界面能指路。
  边界：**权限主动要**（见 `REM-01`），不依赖用户自己摸索。

- [ ] **HLT-02 无障碍服务未开的行为**（P0）
  未开时起锁应被拦截并说明；运行中若被关掉，应退回「使用记录」数据源，白名单仍有效（仅实时性下降）。
  两个数据源都没有时才是真正失效 —— 此时必须有明确提示。

- [ ] **HLT-03 定时体检**（P1）
  每 **30 分钟**体检一次：若「在等保护」（有定时时段 / 正在锁机 / 有应用限额）但无障碍被关，发高优先级通知「锁机保护已失效」，点击跳无障碍设置。
  **同一状态只提醒一次**，恢复后自动复位。

- [ ] **HLT-04 守护服务存活**（P1）
  计时 / 锁机 / 限额任一进行中，划掉后台能被拉回。

- [ ] **HLT-05 权限被撤销后的表现**（P1）
  在系统设置里关掉权限再回 App，预期：有明确状态提示，不出现「以为在保护、其实没保护」的静默失效。

- [ ] **HLT-06 电池优化与自启动引导**（P2）
  引导文案在国产 ROM 上能看懂；跳转不出错。

- [ ] **HLT-07 清后台能力边界**（P2）
  确认不会去杀常驻 / 推送进程（`killBackgroundProcesses` 在 Android 8+ 只能清缓存进程），且**跳过自己和系统应用**。

## 附录 C：新增功能时怎么维护这份清单

1. **新增功能**：在对应章节末尾追加条目，编号顺序递增，不要复用已删编号。
2. **修改功能**：找到对应条目，改「预期」；若改出了新的边界，**追加一条**而不是覆盖旧的。
3. **删除功能**：条目改为「已废弃（版本号）」，**不要删除** —— 保留历史可追溯。
4. **修复线上 bug**：在对应模块下加一条**回归项**，并在「边界」里写清症状与成因，避免下次再犯。
5. 每次发版后，把本文件与 `docs/更新日志.md` 一起提交。
